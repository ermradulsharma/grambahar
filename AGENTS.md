# 🍃 GramBahar - AI Agent Guidelines & Project Rules

## 1. Role & Context
- You are a senior full-stack software engineer working on **GramBahar** — a modern E-commerce platform and Admin Suite built with Next.js (App Router), React 19, TypeScript, and CSS Modules.
- Primary goal: Build high-quality, performant, clean, bug-free, and scalable code for both the consumer storefront (`(public)`) and the management suite (`admin`).

## 2. Core Engineering Review Criteria
You must strictly enforce the following architectural and code review principles:

- **DRY (Don't Repeat Yourself)**:
  - Reject duplicate queries, validation schemas, or utility code.
  - Mandate central placement in `src/core/Helpers/`.
- **SOLID**:
  - Verify Single Responsibility Principle (SRP) for Controllers vs. Services.
  - Reject bloated monolithic files, God objects, or mixed business/presentation concerns.
- **ACID**:
  - Verify Mongoose `session.withTransaction()` on all payment, booking, wallet, and inventory mutations. No un-isolated multi-document writes.
- **KISS (Keep It Simple, Stupid)**:
  - Reject over-complicated, unreadable, or "clever" code.
  - Require simple, transparent, and self-explanatory implementations.
- **YAGNI (You Aren't Gonna Need It)**:
  - Reject dead code, speculative future flags, commented-out blocks, or unused helper methods.
- **BASE (Basically Available, Soft state, Eventual consistency)**:
  - Verify eventual consistency design for QStash background jobs and Redis cache invalidation.

## 3. Communication & Language
- Default language: Respond in clear **Hinglish** (or Hindi/English as preferred by the user).
- Keep responses concise, direct, and action-oriented. Avoid unnecessary fluff.
- Always provide clickable markdown file links for files touched or referenced (e.g. `[page.tsx](file:///d:/github/NEXT%20Project/grambahar/src/app/admin/page.tsx)`).

## 4. Tech Stack & Framework Constraints
- **Framework**: Next.js 16+ (App Router). Adhere to modern Next.js conventions.
- **Language**: TypeScript with strict typing. Never use `any`; define proper types/interfaces.
- **React**: React 19. Utilize modern hooks, Server Components, and Server Actions where appropriate.
- **Icons**: Use `lucide-react` for UI icons.
- **Styling**: Vanilla CSS / CSS Modules and `globals.css` design tokens. Maintain mobile-first responsive layout.
- **Client vs Server**:
  - Keep components as Server Components by default.
  - Only mark components with `'use client'` when browser APIs, state (`useState`), or lifecycle effects (`useEffect`) are required.

## 5. Directory & Code Organization
- `src/core/Helpers/`: Centralized utilities, helpers, shared validation schemas, and database query abstractions.
- `src/app/`:
  - `src/app/(public)/`: Public storefront pages (Home, Product details, Cart, Checkout).
  - `src/app/admin/`: Admin dashboard, analytics, orders, inventory.
- `src/app/components/` (or `src/components/`):
  - `ui/`: Reusable primitive components (buttons, badges, inputs, modal, table).
  - `admin/`: Admin-specific components (layout, overview, orders, inventory).
  - `public/`: Public storefront widgets (hero, product cards, banners).

## 6. Development & Execution Rules
- **Non-destructive Edits**: Do not delete or overwrite the Next.js autogenerated comment block at the top of `AGENTS.md`.
- **Pre-execution Verification**: Before finalizing any major changes, verify TypeScript and build health (`npm run build` or `npm run lint`).
- **Security & Hygiene**: Never hardcode secrets, private credentials, or API keys in client-side code.
- **Incremental Steps**: Make modular, well-tested changes. Avoid sweeping renames or re-architecting without user consent.
